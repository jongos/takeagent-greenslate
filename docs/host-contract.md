# Host integration contract

This package is a development adapter, not an authenticated service. `integration-manifest.json` may describe development availability in TakeAgent; `liveEnabled` must remain false until the gates are met.

Call `previewCsv(buffer, metadata, access, now)` or `await previewXlsx(buffer, metadata, access, {sheetName, now})` from `src/files.js`. For JSON use `preview` from `src/adapter.js`. `metadata` is the fixture object without `rows`; the parser supplies rows and source-row positions. Supply the explicit mapping, source totals, currency, as-of date, revision, project and accounting bases. The host must never derive trusted access from submitted metadata. Resolve access from authenticated account/project ownership on each request and revision comparison, check billing and revocation, and authorize source-project mapping before parsing.

Use a strict allowlist of the supported fixture metadata keys. Keep raw upload bytes only for the approved retention interval, in tenant/project-scoped storage. Prevent cross-project reuse by validating the immutable source project mapping. Do not log files, parsed rows or raw parser exceptions. Catch errors and return a redacted validation failure. Parse in an isolated bounded worker/process with CPU, memory and wall-clock limits before accepting hostile production uploads. Archive byte and record limits in this library are useful input guards, not a process sandbox.

Output has integer minor-unit amounts, separate cost fields, source row numbers, provenance, import timestamp, warnings and a stable fingerprint. CSV source rows are physical end-line numbers for multiline records; XLSX source rows are worksheet rows. Unselected workbook sheets are not emitted, but the XLSX library parses the workbook internally, so minimize uploads to a selected-only workbook before transmission. Hidden selected content is rejected. Parent/header records must be excluded explicitly. No formulas or macros run and formula cells are rejected, even with cached values. Do not transform formatting-only numeric account codes: identifiers must be strings.

Show a transmission/mapping preview and source totals; do not write to finance plans, committed funding or accounting services. Bind any future apply consent to account/project, fingerprint and revision, recheck version at apply, and make duplicate fingerprints idempotent within the project. The present library has no apply method or database. `compare` expects previously validated snapshots from trusted storage, not arbitrary client JSON. Redact/escape source strings in UI, including account codes; they are untrusted data. Cost changes may prompt review, but are not proof of funding gaps or cash timing without separate finance-plan evidence.

On disconnect, revoke source credentials if introduced, stop jobs and delete stored files/snapshots according to policy. This stateless package cannot implement host deletion, authorization or billing. No data is retained by the package itself.
